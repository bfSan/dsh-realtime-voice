# 独立语音总管与可靠回拨

日期：2026-09-20
状态：方向已获认可；详细设计待用户审阅
基线：v0.1.0-alpha.18，DSH 0.1.5-rc.2

## 目标与边界

用户可以不打开聊天框就拨打语音电话，选择项目与执行 Agent，安排新工作、纠正进行中的工作、查询并听取既有结果。电话不永久绑定某个执行会话；每项执行操作必须明确指向具体任务。

本轮仅修改语音插件。保留现有聊天框拨号入口和凭据管理。不修改 DSH 源码、真实项目或模型凭据。不扩展 ChatGPT 跨应用执行桥，不承诺应用退出后的系统来电。

## 已有证据

- session-a437a173 的交接记录把“汇报啊”扩写成合并两份文件，执行 Agent 随后执行了合并；这是意图失真。
- 同会话的“100 字工作汇报”被补写成“无待办、系统空闲”，不能作为实际工作结果。
- Host 日志在 22:25、22:28 出现 no active response；现有取消错误处理依赖瞬时 suppressedResponses 状态。尚需关联取消请求和播放事件才能确定停播完整原因。
- 当前仅在 conversation.input.right 注册拨号入口；工具固定面向绑定 Agent，没有任务目录和结果查询工具。
- 已读操作先隐藏列表条目，再异步请求删除，未确认服务端成功；稍后操作没有明确可见状态。
- 现有 UI 测试模拟回调，不证明真实浏览器的布局、网络请求与播放时序正常。

## 方案选择

1. 只修按钮并加强现有提示词：改动小，但仍依赖当前聊天框，无法可靠跨任务汇报。
2. 独立语音总管加显式任务路由：采用此方案，复用 DSH 执行会话、项目和 Agent preset。
3. 新建独立语音执行 Agent：增加第二套工具、上下文和权限体系，本轮不采用。

## 用户流程

全局入口在无会话页面和任何聊天页面均可访问。拨号不创建执行任务；用户可以先交流、查结果，再决定安排工作。

电话面板可选择项目与 Agent preset，并展示最近任务、运行状态和待汇报事项。现有聊天框入口可提供当前会话作为默认候选，但用户可以切换。Agent 默认指 DSH 已配置的 preset；已有任务沿用原 preset，不在执行途中隐式更换模型或权限。

新工作缺少项目或 Agent 时先简短询问，可使用用户明确保存的默认选择。有歧义时不得根据当前打开的聊天页面自行推断。

“听一下汇报”先查询结果；多个候选时询问是哪项。“写一份汇报”属于新执行意图，但主题或依据缺失时先澄清。“修改/合并汇报”必须来自用户明确要求。查询汇报不得创建文件修改任务。

## 职责与工具

语音连接持有通话上下文和可选择的任务引用，不持有唯一固定执行目标。每个 handoff 记录 taskId、sessionId、workspace、preset、用户原话和执行意图。

新增宿主工具：列举项目与 Agent、列举任务、读取任务状态与结果、选择目标、创建任务、向具体任务 queue/steer、停止任务。使用 DSH 原生控制器；已核对 sessionController 的 create 支持位置与 preset 配置。实现前继续核对目录服务及全局 UI 插槽。

每个有副作用的调用校验目标和用户本次意图。重复交接以通话、用户轮次、目标和意图建立幂等记录。查询工具可以重复使用，但不得因此重复执行工作。

审批和提问通过 interactionId 与所属 sessionId 路由，不能因用户切换关注任务而回答错对象。

## 两套指导配置

- 语音总管指导：影响澄清、任务选择、查询与口头汇报；新增独立配置，可填 Skill 名或 Markdown 路径，并提供内置默认指导。
- 执行 Agent 指导：保留现有 handoffSkill 与附加指令，仅随执行交接下发。

用户留空时语音总管仍具有基本澄清规则；执行指导保持可选。配置显示加载成功或错误，不静默假装生效。无项目时只能加载全局 Skill 或明确路径；项目 Skill 在选择项目后解析，切换项目后更新指导。

指导不能覆盖权限、工具事实或用户明确指令。语音模型通过工具取得任务事实，不能靠 Skill 补造事实。

## 可靠回拨与播放

回拨条目按稳定任务/轮次/交互标识关联。状态区分待接听、连接中、播放中、被打断、已汇报、已读、稍后和失败。

接听先确认语音连接 ready，再投递指定结果；不得在发送注入时就标记已汇报。以供应端响应结束和客户端播放排空共同确认播放完成。中途打断或断线保留可重听状态。明确选择重听允许再次播报；自动事件和历史恢复不得重复投递同一结果。

取消请求带关联标识。已结束响应的取消错误只结算对应取消请求，不中断整个电话；鉴权、协议和连接错误仍须反馈。保留用户真实打断能力，不能靠禁用麦克风掩盖误触发。

增加最小诊断事件：接听、ready、投递、response 创建/结束、取消来源、播放排空和条目状态转换。默认不记录音频、Key、完整提示词或用户正文；用于复现接听即停播的时序。

## 列表交互

每行采用固定选择列、可收缩标题列和操作行。长标题截断，窄窗口操作换行；checkbox 保持固定尺寸并与标题对齐。验证宿主 CSS 影响，不以 jsdom 代替布局验收。

- 接听：显示连接中，防止重复点击；失败保留条目并给出原因。
- 稍后：立即停铃，显示已稍后，条目仍可手工接听。
- 已读：应用内确认框说明仅移除待汇报条目、不删除执行会话；等待宿主确认后更新界面，失败可重试。
- 待回答条目的已读：确认框额外说明该问题将交还 DSH 文字界面，不代表同意或拒绝。

铃声由明确的计时状态管理，轮询不得重置或提前停止；接听、稍后和确认已读按对应条目停止提示。

## 兼容、持久性与实施顺序

保持旧聊天入口。独立通话能力采用显式协议能力协商；不把旧客户端必填 sessionId 静默改为可空。旧直连客户端继续原有绑定行为，不宣称本轮具备独立总管能力。

回拨元数据通过 DSH 存储服务持久化，恢复后对照权威会话状态；待审批恢复必须重新核验有效性，不能恢复旧批准。重启后不自动重放已播内容，未完成条目恢复为待接听。

实施分为：先补时序诊断和回归复现；修列表与播放确认；接入任务目录及路由；增加全局电话入口和语音总管指导；最后整体验收。每阶段保持可运行，不一次性替换全部媒体链路。

## 验收

1. 真实 DSH Desktop 中长短标题、窄宽窗口、收起后挂断的列表均可操作，checkbox 不错位。
2. 已读取消无变更，确认成功才移除；网络失败保留条目；DSH 会话始终存在。
3. 设置 10 秒响铃后跨多次轮询正常计时；稍后立即停铃并可重新接听。
4. 接听后无用户讲话时完整播放；真实插话及时停播，条目可重听；无活跃响应的取消不结束通话。
5. 任务完成、历史恢复与轮询同时到达时只自动汇报一次。
6. 无聊天会话也能拨号，选择项目和 preset 后创建任务；切换聊天页面不改变执行目标。
7. 两项任务并存时“汇报一下”先澄清或明确读取选中任务；绝不转化为合并文件。
8. 同任务补充走 steer，另一项新工作明确创建任务；提问和审批回到正确任务。
9. 两套指导各自加载、配置错误可见；日志不含密钥。
10. 自动化涵盖状态转换、竞态和宿主接口；真实桌面验收与人工麦克风听感单独记录，不能以测试通过替代。
